# Steam 愿望单价格追踪

一个**单文件**的 Steam 愿望单价格追踪页，外加一套「每天自动刷新 + 邮件日报」的云端工具链。

- 页面本体：`index.html`（纯静态，无框架、无构建）
- 自动化工具：`tools/daily-refresh.mjs`（Node，跑在 GitHub Actions 上）
- 定时任务：`.github/workflows/daily-refresh.yml`

> 数据默认只存在**你自己浏览器**的 localStorage 里，不会上传到任何服务器。
> 只有当你主动点「☁️ 同步到云端」时，才会把一份副本写进本仓库的 `data/wishlist.json`，供云端定时任务读取。

## 1. 页面功能

| 区域 | 说明 |
| --- | --- |
| **添加区**（默认展开） | 输入 AppID 或商店链接，回车即可添加 |
| **工具区**（默认收起） | 搜索、筛选、系列分组、导出/导入、云端同步等 17 个控件 |
| **数据概览**（默认收起） | 顶部的款数/促销/达目标/史低/合计卡片；收起时标题栏显示一行摘要 |
| **筛选小标签** | 工具区收起时，已启用的筛选会以小标签显示在标题栏，点 `×` 可单独清除 |
| **筛选计数** | 每个筛选下拉的每一档都带数量，并都有「全部 X」一项（只清该维度） |
| **系列分组** | 默认**关闭**，只有你点了工具栏「📚 系列分组」才会归组显示 |
| **列表可视高度** | 一屏至少能看到 **10 行**（1080p 下约 12 行），按行高自动撑开 |

### 关于「工具区折叠」

原来所有按钮平铺在一起，图标多、视觉噪音大。现在拆成三个可折叠分区：

- **添加区**：保持展开，因为这是高频操作。
- **工具区**：默认收起，点标题栏即可展开/收起。
- **数据概览**：默认收起，点标题栏即可展开/收起。

**所有原有控件一个都没删**，只是搬进了可折叠容器。折叠状态下如果有筛选生效，标题栏会显示小标签和数量角标，不会让你忘记自己开了什么筛选；数据概览收起时也会用一行字汇总关键数字。

折叠/展开状态会记在 localStorage，刷新后保持你上次的选择。

### 关于「筛选计数」

每个筛选维度的数字是**条件计数**：算某一档的数量时，会假装该维度自己没被选中，但**其他维度仍然生效**。

也就是说，「商店筛选 = 促销」时，「类型」下拉里显示的 `动作 (3)` 表示——在"商店=促销"的前提下，换成"类型=动作"会剩下 3 条。这正好回答"我切到这一档会看到几条"。

每个下拉的第一项都是「**全部 X**」，点它只清掉**该维度**的筛选，不会动其他维度。

## 2. 部署步骤

假设你已经有一个 GitHub 仓库（例如 `TicianLi/wishlist`）并开了 GitHub Pages。

把下面这些文件复制进仓库根目录：

```
index.html                             ← 页面本体（覆盖原有的）
package.json                           ← 声明 nodemailer 依赖
tools/daily-refresh.mjs                ← 刷新脚本
.github/workflows/daily-refresh.yml    ← 定时任务
data/                                  ← 空目录即可，之后由「同步到云端」写入
```

然后：

```bash
git add .
git commit -m "feat: 折叠工具栏 + 可折叠统计卡 + 列表至少10行 + 筛选计数 + 开箱即锁的隐私门 + 每日自动刷新"
git push
```

推送后 GitHub Pages 会自动重新发布（通常 1 分钟内生效）。

### 给 Actions 写权限

定时任务需要把刷新后的数据提交回仓库：

**仓库 → Settings → Actions → General → Workflow permissions → 选 `Read and write permissions` → Save**

这一步不做的话，定时任务会在「把刷新后的数据提交回仓库」那一步失败。

## 3. 设置访问密钥（隐私门）

> **默认已启用。** 页面开箱即锁：任何人拿到网址，都必须输入访问密钥才能看到内容。
> 当前默认密钥是 **`579200`**（可以在 `index.html` 的 `GATE_CONFIG` 注释里看到明文提示，方便你自己记）。

锁屏长这样：中间一个锁图标 + 一个密码输入框，**在输对密钥之前，主内容（表格、统计、toast）全部不可见**——不是遮罩，是真的 `visibility:hidden`。

### 为什么开箱就锁

因为这是给别人看的一个私有清单。如果默认敞开，你不小心把链接发出去，别人就直接看到了。现在默认锁定，只有知道密钥的人才能进。

密钥以 **加盐 SHA-256** 比对：`hash = SHA-256(salt + ':' + 明文)`。源码里只有 hash，没有明文。即使用哈希算法也**不能反推出密钥**（只能暴力枚举，成本高）。

### 本站的密钥来源有三层

| 优先级 | 来源 | 谁在用 |
| --- | --- | --- |
| 1 | localStorage `sw_gate_hash` | 你在设置面板里改的密码（**只对本机生效**） |
| 2 | `GATE_CONFIG.hash`（源码默认） | 所有访客 |
| 3 | 站主豁免 `sw_gate_owner_v1` | 只有你自己那台机器 |

**关键点**：你在设置面板里改密码，只会写进你自己浏览器的 localStorage，**不会**改变源码——所以访客用的仍然是源码里的默认密钥。要让**所有人**都改用新密钥，需要把新 hash/salt 写回 `index.html` 并 push。

### 怎么改成你自己的密钥

1. 打开网站，用默认密钥 `579200` 进入。
2. 点右上角 **⚙️ 设置** → **访问密钥** → **修改访问密钥**。
3. 输入新密钥（建议 6 位以上），确认。
4. 页面上会弹出新算出来的 `hash` / `salt`——**照着控制台/提示框里的值**，把它们粘进 `index.html`：

```js
const GATE_CONFIG = {
  hash: '把这里换成新算出来的 hash',
  salt: 'sw-gate-v1',        // 如果你也改了 salt，一起换
  rememberDays: 7,
  ...
};
```

5. `git push`，等 Pages 重新发布。

改完之后，**任何访客**都要用你的新密钥。你自己那台机器因为被标记为「站主」，所以会**免密钥直接进**，不会被自己锁在门外。

### 站主豁免（本机免密钥）

「站主豁免」= 这台设备**永久免输密钥**。它是一种特权，所以发放有门槛：

- **必须先在锁屏输入一次正确的密钥**，验证通过才会写标记。
  - 点锁屏底部「**我是站主，申请本机免密钥**」→ 弹出输入框 → 输入正确密钥 → 通过。
  - 已经用密钥进过站的人（有有效凭证）点它则直接生效，不用再输。
  - ⚠️ 输错密钥 → **不会**发放豁免，并提示"密钥不正确"。
- 标记存在 localStorage 的 `sw_gate_owner_v1`，**只在你这台机器/这个浏览器生效**，别人打开你的链接不会继承。
- 换电脑、清浏览器数据后标记消失，用密钥重新申请即可。

> 🔒 **为什么要有这个门槛**（重要设计说明）：
> 如果谁点一下就能免密钥，那密码门就白设了——访客输对一次密钥进来后，点一下按钮就永久免密钥，
> 以后连密码都不用输了。所以「免密钥」这个特权必须**凭密钥换取**。

#### 另外：改密钥、取消密钥这些操作也受保护

设置面板里的「修改访问密钥」「取消访问密钥」会在执行前检查 `gateOpAllowed()`：
本机没有有效凭证（也没豁免）时会直接拒绝并把你拉回锁屏。
这样即使有人绕过界面直接调用这些函数，也改不动密钥、拿不到豁免。

### 锁屏长什么样

- 深蓝渐变背景 + 缓慢浮动的光点，中间一张毛玻璃卡片。
- 圆形锁图标、标题、说明文字。
- 密码输入框带 **👁 显示/隐藏** 按钮。
- 「记住我（7 天内免输入）」勾选框。
- 底部说明 + 「我是站主，申请本机免密钥」按钮。
- 输错时输入框会**抖动** + 红色提示。

### 设了密钥之后

- 访问者会先看到锁屏，输对密钥才能进。
- 勾选「记住我」可免密 7 天（`rememberDays` 可调）。
- 密钥错误会有连续错误计数提示，防止暴力尝试。
- 改密钥后，旧凭证立即失效。
- 想取消本机密码：设置面板里点 **取消密码**——注意，这只会清掉你本机的覆盖值，**页面会退回源码默认密钥并保持锁定**，不会变成公开访问。要真的恢复公开，才需要把 `index.html` 里的 `hash` 改回 `''`。

### 请注意

这是**前端**密钥门，能挡住「随手点进来的人」和搜索引擎/爬虫，但挡不住有技术的人（因为校验逻辑在浏览器里，理论上可以绕过）。要真正硬核的访问控制，见[第 8 节](#8-进阶更严格的访问控制)。

## 4. 配置每日 02:00 自动刷新 + QQ 邮件

> 📘 **完整的图文步骤见 [`部署指南-自动刷新与QQ邮件.md`](./部署指南-自动刷新与QQ邮件.md)**
> 下面是精简版，遇到问题或想要更细的截图级说明请看那份。

### 4.1 拿到 QQ 邮箱授权码

**不能用登录密码！** 必须用授权码：

1. 登录 [QQ 邮箱网页版](https://mail.qq.com) → 设置 → 账户。
2. 找到 **IMAP/SMTP 服务** → 开启。
3. 按提示发一条短信，拿到一串 **16 位授权码**（形如 `abcdwxyzefghijkl`）。
4. 复制保存好，稍后填进 Secrets。

### 4.2 添加 Secrets

**仓库 → Settings → Secrets and variables → Actions → New repository secret**，逐个添加：

| Name | Value | 必填 |
| --- | --- | --- |
| `SMTP_HOST` | `smtp.qq.com` | ✅ |
| `SMTP_PORT` | `465` | ✅ |
| `SMTP_USER` | `你的QQ号@qq.com` | ✅ |
| `SMTP_PASS` | 上一步拿到的**授权码** | ✅ |
| `MAIL_TO` | 收件邮箱（可以就是你自己） | ✅ |
| `MAIL_FROM` | 发件显示名（不填则用 `SMTP_USER`） | ⬜ |
| `ITAD_API_KEY` | [ITAD](https://isthereanydeal.com/apps/) 的 API Key，用于查史低 | ⬜ |

> `SMTP_PORT` 必须是 **465**（SSL），不要用 587。

### 4.3 时区说明

GitHub Actions 的 cron 用 **UTC**：

- 北京时间 **02:00** = UTC **18:00**（前一天）
- 所以配置是 `cron: '0 18 * * *'`

> ⚠️ GitHub 的定时任务在高峰期可能延迟 5～15 分钟，这是平台行为，不是脚本问题。

### 4.4 手动测试一次

不用等到凌晨。**仓库 → Actions → 每日凌晨自动刷新并邮件导出 → Run workflow**，选 `always` 后运行。

跑完可以：
- 看运行日志确认没有报错；
- 去邮箱收日报；
- 在 Artifacts 里下载那一份 JSON。

## 5. 日常使用流程

```
① 在页面上加游戏、设目标价、写备注
        ↓
② 点工具栏「☁️ 同步到云端」（首次会让你填一次 GitHub Token）
        ↓
③ 每天 02:00 GitHub Actions 自动：
     读 data/wishlist.json
     → 逐个 AppID 重新拉 Steam 价格/评分（可选 ITAD 史低）
     → 把刷新后的数据写回 data/wishlist.json 并提交
     → 导出快照 data/steam-wishlist-YYYY-MM-DD.json
     → 邮件发到你的 QQ 邮箱（JSON 作为附件）
        ↓
④ 第二天早上收邮件，就知道哪些降价了、哪些到目标价了
```

### 关于「☁️ 同步到云端」需要 Token

首次点击会**自动打开设置面板的「云端同步」区块**，在那里填写 GitHub Token：

- 去 <https://github.com/settings/personal-access-tokens/new> 建一个 **Fine-grained token**
- **Repository access**：勾选你这一个仓库（**必须勾**，否则 403）
- **Permissions → Contents**：选 **Read and write**（只给 Read 也会 403）
- Token 存在你本机浏览器，不会外传

设置面板里还能：
- **测试连接**：只读探测，明确告诉你 Token 能不能读到仓库、有没有写权限、分支对不对
- **保存并同步一次**：存配置 + 立刻同步，马上验证 Token 对不对
- **清除 Token**：一键清掉
- 随时改仓库所有者 / 仓库名 / 分支 / 文件路径

> 早期版本 Token 是弹窗一次性输入的，**填错了没地方改**。现在改成设置里的常驻表单项，随时可改。
>
> 遇到 `HTTP 403: Resource not accessible by personal access token` 请看
> [部署指南里的 403 排查](./部署指南-自动刷新与QQ邮件.md#-遇到-http-403-resource-not-accessible-by-personal-access-token)。

### 哪些数据会被保护

刷新脚本**永远不会覆盖**你手动填的东西：

- `targetPrice`（目标价）
- `note`（备注）
- `historicalLow.source === '手动确认'`（你手动确认的史低）

另外，单个游戏抓取失败**不会影响整体**，其他游戏照常刷新。

## 6. 可选环境变量

在 workflow 的 `env:` 里可以加：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `STEAM_CC` | `cn` | 定价区，国区就是 `cn` |
| `STEAM_LANG` | `schinese` | 抓取名称/评论的语言 |
| `ITAD_API_KEY` | 空 | 填了才查史低；不填跳过 |
| `MAIL_MODE` | `always` | `always` = 每天发；`changes` = 只在有新变化时发 |
| `REQ_INTERVAL_MS` | `700` | 每个请求间隔，避免被 Steam 限流 |
| `REQ_TIMEOUT_MS` | `20000` | 单请求超时 |
| `MAX_GAMES` | `0` | 每次最多刷新几款，`0` = 不限 |

觉得邮件太频繁？把 `MAIL_MODE` 改成 `changes`：

```yaml
MAIL_MODE: changes
```

## 7. 常见问题

**Q：定时任务成功了，但没收到邮件？**

大概率是 SMTP 配置问题。检查：
1. `SMTP_PASS` 是不是**授权码**（不是 QQ 登录密码）——这是最常见的坑；
2. `SMTP_PORT` 是不是 `465`；
3. QQ 邮箱的 IMAP/SMTP 服务有没有开启；
4. Actions 日志里搜「邮件发送失败」，会写明具体原因。

> 邮件发失败**不会**影响 JSON 导出和数据写回，两者互相独立。

**Q：Actions 报错说找不到 `data/wishlist.json`？**

先去页面点一次「☁️ 同步到云端」，把数据传上去。这是设计如此——没有云端副本就没法在云端刷新。

**Q：定时任务没有在 02:00 准点跑？**

GitHub 的 schedule 在高峰期会排队，延迟几分钟到十几分钟是正常的。急的话可以手动 Run workflow。

**Q：系列分组怎么又打开了？**

不会了。这个问题已经修好：现在默认关闭，只有你点工具栏的「📚 系列分组」才会开，并且刷新后保持你的选择。

**Q：我刷新了页面，数据没了？**

数据存在 localStorage，正常刷新不会丢。但**清除浏览器数据 / 换浏览器 / 无痕模式**会丢。所以建议定期用工具栏的「📤 导出 JSON」备份一份。

**Q：我忘了密钥，自己都进不去了？**

先用默认密钥 `579200` 试试（除非你已经改过源码里的 `hash`）。还是不行的话，两种办法：

1. **本机豁免**：点锁屏底部的「我是站主，本机免密钥」，或者手动在控制台执行
   ```js
   localStorage.setItem('sw_gate_owner_v1','1'); location.reload();
   ```
2. **改源码**：把 `index.html` 里 `GATE_CONFIG.hash` 换成新算的 hash（或临时改回 `''` 先解锁），再 push。

> 注意：**改源码才会影响所有访客**。设置面板里改的密码只写在你本机 localStorage，访客不受影响。

**Q：我给朋友发了链接，他为什么进不去？**

这是设计如此——页面开箱即锁。把你的密钥告诉他就行。他那边不会继承你的「站主豁免」，所以每次（或勾了记住我之后 7 天内）都要输一次。

**Q：别人输对密钥后，能不能也把自己变成"站主"免密钥？**

不能。免密钥是特权，**必须凭正确密钥换取**：点「申请本机免密钥」时还会再让你输一次密钥，输错就不给。
就算他自己手动往 localStorage 里写标记，那也只是**他自己那台机器**免密钥，改不了你的页面、也拿不到你的数据权限——
他本来就已经有密钥能看了。真正的边界是「**密钥本身**」，不是这个标记。

> 早期版本确实有漏洞：进站后点一下就能白拿豁免。已在当前版本修掉，并有 `tools/_test_gate_sec.cjs` 专门回归守护。

**Q：列表打开只看到几行，能显示更多吗？**

已经调整过了：列表容器高度会按行高自动撑开，**一屏至少 10 行**（1080p 下 12 行）。如果你觉得还不够，可以收起顶部的「数据概览」卡片，省下来的空间会给列表。

**Q：筛选下拉里的数字是怎么算的？**

是**条件计数**——算某一档时假装该维度未选中，其他维度照常生效。所以数字会随你当前的其他筛选变化。这正好告诉你「切到这一档会看到几条」。每个下拉顶部的「全部 X」只清该维度。

## 8. 进阶：更严格的访问控制

前端密码门的定位是「挡住随手访问的人」。如果你需要**真正的**访问控制（比如里面有敏感内容、或者不想让任何人猜到链接），推荐用 **Cloudflare Access**：

1. 把站点托管到 Cloudflare Pages（或把域名解析切到 Cloudflare）。
2. 开启 **Zero Trust → Access → Applications**，把站点加进去。
3. 策略设为「只允许指定邮箱」，访问时需要邮箱收验证码。

这样做的好处：
- 校验发生在**服务端**，页面 HTML 根本不会发给未授权的人；
- 支持邮箱白名单、时间窗口、设备信任等；
- 免费额度对个人使用完全够。

代价是配置比一个密码框麻烦一些。如果你只是不想让朋友/同事随手点进来看到，当前的密码门就够了。

```bash
npm install          # 只需装 nodemailer
```

```
SELFTEST PASS 11  FAIL 0
```

### 连通性自检页

`连通性自检.html` 是给用户排查 `Failed to fetch` 用的**独立只读诊断页**，
不依赖 `index.html`，但要靠 `index.html` 同目录部署才能同源访问：

```
https://ticianli.github.io/wishlist/连通性自检.html
```

它逐跳测：页面协议 → `navigator.onLine` → `api.github.com/rate_limit` →
`githubstatus.com` → 匿名配额 → 带 Token 读仓库，最后给出三方结论之一：
「网络层被拦」「网络可达但 Token/仓库配置有问题」「一切正常」。
